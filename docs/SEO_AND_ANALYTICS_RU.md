# SEO, индексация и аналитика лендинга

Рабочий чеклист. Ветка `day14`, репозиторий `sosed.place`. После приёмки тот же подход
повторяется на `neighbro.place` (тот же движок лендинга, другой домен и словарь).

Репозитории:

- лендинг сосед — <https://github.com/panov-id/sosed.place>
- лендинг neighbro — <https://github.com/panov-id/neighbro.place>
- монорепо (панель, функции, скрипты) — <https://github.com/panov-id/xor.ad>

## Исходное состояние

- `landing/index.html` — одна статическая страница, отдаётся с Bunny CDN storage.
- 17 языков живут в JS-словаре `T` и переключаются на клиенте (`applyLang`).
  Для краулера это значит: **в индекс попадает только русская версия**, все переводы
  невидимы — URL один, HTML в ответе один.
- Нет `robots.txt`, нет `sitemap.xml`.
- CSP жёсткая: `default-src 'self'`, внешние скрипты запрещены.
- Аналитики нет вообще.

## Целевое состояние

- `sosed.place/` — русский, `sosed.place/en/`, `/de/`, `/fr/` … — по странице на язык,
  каждая с готовым переведённым HTML в ответе сервера.
- Взаимные `hreflang` между всеми языками + `x-default` на корень.
- `robots.txt` + `sitemap.xml` со всеми языковыми URL.
- GA4, подключаемый флагом окружения; на dev/uat выключен.
- Cookie-баннер: до согласия GA4 не грузится.

## Чеклист

### A. Индексация

- [x] **A1. `landing/robots.txt`** — обход разрешён, указан sitemap. На непроде файл
      подменяется на `Disallow: /`.
- [x] **A2. `landing/sitemap.xml`** — пока статический: корень, `rules.html` и две
      юридические страницы. Раздел B заменит его на генерируемый, с 17 языками и
      взаимными `hreflang`.
- [x] **A3. Верификация Google Search Console** — meta-тег вставляется на деплое из
      `SEARCH_CONSOLE_TOKEN`, только на проде; токен в репозиторий не попадает.
- [ ] **A4. Отправить sitemap в Search Console** после первого прод-деплоя.

### B. Мультиязычные страницы

**Решение по умолчанию:** корень `sosed.place/` — **английский**, `x-default` ведёт на
него же. Русский живёт в `/ru/`, как и все остальные языки в своих папках.

- [x] **B1. `landing/build-pages.mjs`** — генератор. Логика извлечения словаря вынесена в
      общий `landing/i18n-dictionary.mjs`, который теперь читают и генератор, и
      `check-i18n.mjs`. Подставляет тексты в `[data-i18n]` и `[data-i18n-ph]` прямо в
      разметку, пишет корень на английском и 16 языковых папок. Словарь остаётся
      единственным источником правды — ручных копий страниц нет.
- [x] **B2. Переведённый `<head>`** в каждой странице: явный `<html lang="…">`,
      `title`, `description`, `og:title`, `og:description`, `og:url`, `og:locale`,
      `canonical`. Тексты собраны из существующих ключей (`brand`, `h1a`, `h1b`, `sub`) —
      новых строк переводить не понадобилось.
- [x] **B3. Блок `hreflang`** — 17 языков + `x-default` на каждой странице, взаимно.
      Проверено: у всех страниц по 18 альтернатив и каждый адрес существует файлом.
- [x] **B4. Переключатель языка ведёт на URL** (`/de/`). На сгенерированных страницах —
      навигация, на исходном файле без маркера языка — прежняя подмена текста, чтобы
      локальная разработка работала без запуска генератора.
- [x] **B5. Мягкий языковой редирект** — только на корне, только при первом заходе и
      только если язык браузера у нас опубликован. Выбор сохраняется до перехода, поэтому
      петля невозможна.
- [x] **B6. `<base href="/">` в языковых страницах.** Из папки `/de/` все относительные
      ссылки вели бы внутрь этой папки. Одна строка чинит и `href`/`src`, и `url()` в
      инлайновых стилях, и регистрацию service worker. Работает, пока на странице нет
      якорных ссылок — генератор падает с внятной ошибкой, если такая появится.

### C. Аналитика

- [x] **C1. Флаг `analyticsId` в `config.js`** — пустой по умолчанию; `deploy-landing.sh`
      подставляет `ANALYTICS_ID`, воркфлоу прода берёт его из секрета. dev и uat остаются
      пустыми, то есть без счётчика и без баннера.
- [x] **C2. Загрузчик GA4** — грузит `gtag.js` лениво и только при наличии ID и согласия.
- [x] **C3. CSP** — расширены `script-src`, `img-src`, `connect-src` под домены Google.
- [x] **C4. Событие отправки формы waitlist** — `waitlist_signup` с языком страницы.
- [x] **C5. Свой счётчик просмотров** (27.07.2026) — `POST /pageview` на релее, рядом с
      `/client-error`: бренд определяется ключом, запись ложится в пространство
      арендатора, страница «Page views» в панели поверх `LogExplorer`.
      **Работает без согласия и потому считает всех** — в записи нет ни адреса, ни
      user-agent, ни идентификатора; на устройстве не остаётся ничего, кроме флага в
      `sessionStorage`, живущего до закрытия вкладки. Реферер сокращается до хоста
      (в полном адресе бывают поисковые запросы), ширина экрана — до корзины
      mobile/tablet/desktop. GA4 остаётся за согласием и даёт детали; свой счётчик даёт
      честную базу без пропусков. CSP не трогали: запрос идёт на свой же бэкенд.

### D. Согласие на куки

- [x] **D1. Баннер согласия** — в стилистике лендинга, кнопки «принять» /
      «только необходимое», выбор в `localStorage` (`ss-consent`).
- [x] **D2. GA4 не грузится до согласия.** Отказ — счётчика нет вообще.
- [x] **D3. Тексты баннера в словаре `T`** — 4 ключа во всех 17 языках,
      `check-i18n.mjs` подтверждает полноту.
- [x] **D4. Раздел про аналитику и куки в `legal/privacy_EN.md`** + ссылка из баннера.
- [x] **D5. Кнопка «куки» в футере.** Появляется после того, как выбор сделан, сбрасывает
      `ss-consent` и снова показывает баннер — отозвать согласие теперь так же просто, как
      дать. Сделана именно кнопкой, а не ссылкой: `href="#"` сломал бы языковые страницы,
      которые держатся на `<base href="/">`. Текст переведён на все 17 языков
      (`cookieSettings`).

### E. Сборка и деплой

- [x] **E1. `deploy/deploy-landing.sh`** — прогоняет генератор по staging-копии перед
      загрузкой в Bunny и удаляет из неё сами `.mjs`-скрипты. `SITE_ORIGIN` задаёт домен
      окружения, чтобы на dev и uat canonical не указывал на прод.
- [x] **E0. `deploy/run-node.sh`** — единая точка входа для Node-инструментов лендинга:
      `node:22-alpine` с примонтированным репозиторием. На хосте Node не запускается.
      `RUN_NODE_NATIVE=1` — режим для CI, где Node уже стоит на раннере.
- [x] **E2. `actions/setup-node@v4` с Node 22 в трёх воркфлоу** — вызов идёт через
      `run-node.sh` с `RUN_NODE_NATIVE=1`, то есть локально генератор работает в
      контейнере, а в CI напрямую на раннере.
- [x] **E3. `sw.js`** — офлайновый фолбэк для навигации теперь отдаёт оболочку своего
      языка (`/de/`), а корень (английский) остаётся лишь последним запасным вариантом.
- [x] **E4. `check-i18n.mjs`** — проверяет новые ключи автоматически: он сверяет объединение
      ключей всех языков с тем, что размечено в HTML, так что баннер, кнопка отзыва и FAQ
      попали под проверку без правок самой проверялки.
- [x] **E5. `SPEC_RU.md` / `SPEC_EN.md`** — добавлены разделы про адреса и языки и про
      аналитику с согласием; поправлено утверждение «без сборки», которого больше нет.
      Запрет на якорные ссылки зафиксирован там же, чтобы не всплыл через полгода.

### F. Проверка

F1–F3 закрыты `landing/verify-seo.mjs`: он читает уже сгенерированный сайт, то есть
отвечает на все три вопроса **до** выката. Прогон: собрать копию генератором во
временную папку и запустить проверку через `deploy/run-node.sh`. Проверено 27.07.2026
на обеих витринах — sosed (17 языков, sitemap из 19 адресов) и neighbro (10 языков,
12 адресов), обе зелёные.

- [x] **F1.** Языковая страница отдаёт переведённый HTML без выполнения JS —
      сверяется `<html lang>` и строка из словаря прямо в разметке.
- [x] **F2.** `hreflang` взаимны: у каждой страницы 17 языков + `x-default`, и каждый
      адрес существует файлом.
- [x] **F3.** `sitemap.xml` разбираем (один `urlset`, парные `<url>`), все адреса
      существуют файлами. «Отвечают 200» проверится на проде, но мёртвых ссылок в
      сборке уже нет.
- [ ] **F4.** Без согласия — ни одного запроса к доменам Google (проверка в devtools).
- [ ] **F5.** CSP не ругается в консоли ни в одном режиме.

## Найдено при независимом разборе

По убыванию влияния. Пункты G1–G3, на мой взгляд, стоит сделать в этом же заходе.

- [x] **G1. Непродовые окружения не индексируются.** `LANDING_ENV` в трёх воркфлоу;
      всё, кроме `prod`, получает `robots.txt` с `Disallow: /`, meta `noindex` во всех
      HTML и удалённый sitemap. Незаданная переменная трактуется как непрод — безопасное
      значение по умолчанию.
- [x] **G2. Один канонический хост — сделано.** На зоне `sosed-prod` (6123213) стоит edge
      rule «seo: www to apex»: 301 с `www.sosed.place` на апекс с сохранением пути и
      query (`https://sosed.place{{path}}`, без хвостового слэша — иначе получается
      двойной). Проверено: `www.sosed.place/legal.html?doc=privacy` → 301 на тот же путь
      без www. Синтаксис предварительно обкатан на dev-зоне и там убран.
- [x] **G3. Тонкий контент — вылечен блоком FAQ.** На странице появились шесть вопросов
      (что это, нужен ли профиль, как работает совпадение, почему сообщения тают, видно ли
      где ты живёшь, когда запуск) — переведены на все 17 языков. Генератор собирает из
      тех же ключей разметку `FAQPage`, поэтому видимый текст и структурированные данные
      физически не могут разойтись, а каждая языковая страница получает разметку на своём
      языке. Проверено: JSON валиден, шесть вопросов на всех 17 страницах.
- [x] **G4. `JSON-LD Organization` / `WebSite`** — в `<head>` лежит `@graph` с брендом,
      логотипом, почтой, списком языков сайта и `sameAs` на GitHub. Плюс видимая иконка
      репозитория в футере с `rel="me"`. Смысл именно в `sameAs`: так поисковик связывает
      «сосед» с официальными профилями и считает это одной сущностью.
- [x] **G5. Короткий TTL кэша для HTML — сделано.** Было `max-age=2592000` (тридцать
      дней) на всё, включая HTML: purge чистил только край CDN, а в браузере
      вернувшегося пользователя лендинг мог висеть месяц. Теперь edge rule
      «seo: short browser cache for html» даёт 300 секунд для корня, `*.html`, будущих
      языковых папок `/*/`, `robots.txt` и `sitemap.xml`. Картинки, шрифты, скрипты и
      стили сохранили месячный кэш — проверено запросом.
- [x] **G6. `legal.html` и `rules.html`** получили `description` и `canonical`. У
      `legal.html` canonical ведёт на адрес без `?doc=`, поэтому два документа не
      расщепляют индекс; в sitemap теперь тоже адреса без параметра. Заголовок
      `СОСЕД — Legal` заменён на `sosed — Legal` ради единого написания бренда.
- [x] **G7. IndexNow.** Ключ-файл `8f4c1a7e93d6425bb0e2f5c8a1d73096.txt` лежит в корне
      лендинга (он публичный по устройству протокола), деплой прода после заливки шлёт в
      `api.indexnow.org` список URL прямо из сгенерированного sitemap. Bing и Яндекс
      узнают об изменениях, не дожидаясь обхода. Регистрация в Bing Webmaster Tools —
      отдельный ручной шаг, для IndexNow она не требуется.
- [x] **G8. `og:locale`** проставляется генератором на каждой странице. Отдельная
      OG-картинка на язык пока не делается: пайплайн в `og/` рисует одну на весь сайт,
      и без переведённой типографики смысла в 17 копиях нет.
- [x] **G9. Core Web Vitals — проверено, чинить почти нечего.** Тегов `<img>` на странице
      нет вообще, вся графика идёт CSS-фонами, поэтому сдвигов макета нет и
      `width`/`height`/`lazy` добавлять некуда. Единственная реальная точка — сплэш,
      который держит экран две секунды и обнаруживается браузером только после разбора
      стилей: ему добавлен `rel="preload"`. Вес картинок умеренный (самая тяжёлая — герой,
      180 КБ).
- [ ] **G10. Страница 404 — упирается в Bunny.** Своя страница написана
      (`landing/404.html`, деплоится и доступна по `/404.html`), но подставить её вместо
      дефолтной не вышло: поле `ErrorPageCustomCode` относится к ошибкам origin, а не к
      404 от storage — проверено на dev-зоне, включение вместе с `ErrorPageWhitelabel`
      тоже ничего не меняет, dev возвращён в исходное состояние. Статус-код при этом
      корректный (404, а не soft-404), так что для индексации это косметика. Остаётся
      вариант с собственным origin вместо storage — избыточно ради страницы ошибки.

## Открытые решения

- Домены Google в CSP — это осознанное послабление политики, которая сейчас
  запрещает любые внешние ресурсы. Приватность лендинга при этом держится на
  баннере согласия: без явного «да» ни один запрос наружу не уходит.
