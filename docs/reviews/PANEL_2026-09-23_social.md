## Вижу дефект

**1. Дефект дизайна — аргумент с `..` рекурсивно удаляет исходники.** `social/render/render.mjs:41` + `:78`. Аргумент лишь обрезается от `social/` и `/`, затем `rm(join(OUT, piece), {recursive:true, force:true})`, при этом репозиторий смонтирован на запись (`run.sh:22`). Сценарий: `run.sh ..` → `join("/repo/social/out","..")` = `/repo/social` — удаляется весь `social/` с постами; `run.sh ../posts` удалит `social/posts`. Сейчас `social/` целиком не отслеживается (`?? social/` в `git status`) — восстановить из git нечего. Не злоумышленник, а опечатка разработчика. Исправление: (а) валидировать аргумент `/^(posts|stories|profile)\/[A-Za-z0-9_-]+$/`, иначе падать; (б) дополнительно проверять `resolve(OUT, piece)` начинается с `OUT + sep`.

**2. Мелочь (теоретическая) — префиксная проверка пути в статическом сервере.** `render.mjs:28-29`: `join(REPO, "/../repo-evil/x")` → `/repo-evil/x`, и `startsWith("/repo")` его пропустит. В контейнере REPO=`/repo`, соседних `/repo*` нет; запросы шлёт только наш же Chromium, порт на `127.0.0.1` в netns контейнера, `-p` не пробрасывается — с хоста/сети недоступно. Исправление: `const file = resolve(REPO, "." + path); if (file !== REPO && !file.startsWith(REPO + sep)) 403`; лучше отдавать только `social/` и `landing/fonts*`.

**3. Мелочь — сервер отдаёт весь репозиторий, включая `.git/` и `.claude/settings.local.json`.** `render.mjs:28`. Проверил, что утекать нечему: из игнорируемых в sosed.place есть только `.claude/settings.local.json` (28 строк с token/key/secret, но префиксов реальных ключей `ghp_`/`github_pat_`/`sk-`/`re_` нет); `deploy/` — только скрипты, `.env` в дереве нет; `git remote` по ssh без токена; `landing/8f4c…096.txt` похоже на ключ IndexNow — он публичен по замыслу (не открывал). Сценарий: `post.js` делает `fetch("/.claude/…")` и шлёт наружу — у контейнера есть выход в сеть (`docker run` без `--network none`). Но `post.js` пишет сам владелец, поэтому теоретически. Исправление: белый список префиксов в сервере + `--network none` в `run.sh:20` (рендеру сеть не нужна: шрифты локальные, `photo` в постах — локальные).

**4. Мелочь — неполное экранирование, но граница доверия его не требует.** `kit.js:22` `esc` не экранирует кавычки; `kit.js:289,332` `photo`/`photoPos` вставляются в `style="…url('…')"` без экранирования; `kit.js:337` `T[s.type]` — произвольный ключ. Источник — `post.js`, который владелец коммитит сам и который и так выполняется как скрипт (`kit.js:344-355`); HTML-инъекция ничего сверх этого не даёт. Внешних авторов нет → не дыра. Исправление для аккуратности: добавить `"` и `'` в `esc`, прогонять `photo` через него. Низкий приоритет.

**5. Мелочь — `check.mjs:25` `vm.runInNewContext` не песочница.** Тот же доверенный `post.js`, в контейнере. Ничего не делать, можно отметить в комментарии.

**6. Мелочь (надёжность) — `render.mjs:27` `decodeURIComponent` бросает на `%` в пути.** Исключение в async-обработчике = необработанный reject → Node 15+ завершает процесс. Исправление: обернуть в `try`, отвечать 400.

**7. Мелочь — цепочка поставок.** `Dockerfile:3` образ по тегу `v1.52.0-noble`, не по digest; `Dockerfile:8` `npm install playwright@1.52.0` без lockfile (версия точная, `playwright-core` тянется точной — риск минимальный). `run.sh:13,15` тег `social-render:1.52` не пересобирается при правке Dockerfile (устаревание, не дыра). `fonts/fetch.sh:15,22` curl шрифтов без проверки целостности — одноразово, результат коммитится и проходит ревью, приемлемо. Исправления: `@sha256:…`; хэш Dockerfile в теге; при желании `sha256sum` рядом со шрифтами.
